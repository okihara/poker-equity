# poker-equity

NLHE（テキサスホールデム）の **ハンド vs レンジ** のオールインエクイティを計算する単一ページのツール。
依存パッケージなし・ビルド成果物は `index.html` 1枚で、ダブルクリックすればそのまま動く。

![](https://img.shields.io/badge/deps-none-informational) ![](https://img.shields.io/badge/node-%3E%3D18-informational)

## 使う

```sh
open index.html          # これだけ
```

- ヒーローの2枚とボード（0 / 3 / 4 / 5枚）を選ぶ
- 相手のレンジを 13×13 グリッドで塗る。ドラッグで連続選択、選択済みのマスから始めると消去
- ウェイト 25 / 50 / 75 / 100% で部分レンジを作れる
- 「上位n%」スライダーでレンジを一括生成。プリセット（UTG 8% 〜 SB 45%）もある
- レンジは `AA,KK,AKs,AQo:0.5` 形式のテキストで入出力できる
- 結果は総合エクイティ（勝ち / 引き分け / 負けの内訳つき）と、レンジ内ハンド別のヒートマップ

## 計算方式

**ハンド評価器**（`src/evaluator.js`）はルックアップテーブルを持たない。4つのスート別ランクビットマスクを作り、
その積で「2枚以上」「3枚以上」「4枚」のランク集合を一度に出す:

```js
const p2 = (s0&s1)|(s0&s2)|(s0&s3)|(s1&s2)|(s1&s3)|(s2&s3);  // ペア以上
const p3 = (s0&s1&s2)|(s0&s1&s3)|(s0&s2&s3)|(s1&s2&s3);      // トリップス以上
const p4 =  s0&s1&s2&s3;                                     // クアッズ
```

ストレート判定と上位5枚の抽出は 8192 エントリの小さなテーブルで引く。7枚の評価は
1コールあたり約 35ns（M2 / Node 22 で毎秒 2,800万回）。

**エクイティ計算**（`src/equity.js`）は残りボードの通り数で方式を切り替える:

| ボード | 残りボード通り数 | 完全列挙できるコンボ数 |
| --- | --- | --- |
| 5枚 | 1 | 全レンジ |
| 4枚 | 46 | 全レンジ |
| 3枚（フロップ） | C(47,2) = 1,081 | 全レンジ |
| 2枚 | C(48,3) = 17,296 | 全レンジ（1,326 × 17,296 = 2,293万） |
| 1枚 | C(49,4) = 211,876 | 141コンボまで |
| 0枚（プリフロップ） | C(50,5) = 2,118,760 | 14コンボまで |

`残りボード通り数 × コンボ数 <= 3×10^7` なら完全列挙し、そうでなければコンボ層化モンテカルロに落ちる。
層化（各コンボに同数のボードを割り当てる）にしているのは、ハンド別ヒートマップの各マスにも
十分なサンプルを行き渡らせるため。モンテカルロ時は 95% 信頼区間を併記する。

エクイティはチョップを 1/2 として数え、ウェイトつきレンジでは `Σ w_i·eq_i / Σ w_i` を返す。
ヒーローのカードやボードとぶつかるコンボはレンジから落とすので、ブロッカー効果は自動的に効く。

**「上位n%」の順序**（`src/rank-order.json`）は、169ハンドそれぞれのランダムハンドに対する
オールインエクイティを 1ハンドあたり200万回で実測した順（AA 85.23% 〜 32o 32.27%）。
プレイアビリティ補正は入れていないので、スモールペアは一般的なオープンレンジ表より高く出る。
`npm run rank` で再現できる（シード固定、同じ結果が出る）。

## 検証

```sh
npm test
```

- **交差検証** — 7枚評価器を、C(7,5) の5枚組を総当たりする素朴な実装と 40,000 ショーダウンで照合。不一致ゼロ
- **既知の値** — `AKs vs QQ 46.05%`、`AKo vs QQ 43.24%`、`AA vs KK 81.95%`、`88 vs AKo 55.16%`、
  `AA vs ランダム 85.20%` ほか、完全列挙の結果を小数第3位まで固定
- **不変量** — 勝ち+引き分け+負け = 1、ヒーローとビランのエクイティの和 = 1、
  ウェイトは相対値である（全体を0.5倍しても結果が変わらない）、混合レンジは純粋レンジの間に入る
- **ビルドの鮮度** — `index.html` と `dist/artifact.html` が現在の `src/` のバイト列を含むことを検査する。
  `npm run build` を忘れた状態でコミットするとテストが落ちる

## 構成

```
src/
  evaluator.js      7枚ハンド評価器、カード/レンジのユーティリティ
  equity.js         computeEquity(hero, board, combos, opts)
  app.js            UI（グリッド、カード選択、ヒートマップ、配色）
  app.css           スタイル（ライト/ダーク両対応）
  app.head.html     <title> とフォント
  app.body.html     マークアップ
  rank-order.json   169ハンドのエクイティ順（tools/build-rank.js が生成）
tools/
  build.js          src/ を index.html と dist/artifact.html に組み立てる
  build-rank.js     rank-order.json を再計算する
  load-engine.js    Node から src/ をブラウザと同じスコープで読み込む
test/
  evaluator.test.js
  equity.test.js
  build.test.js
index.html          スタンドアロン版（生成物）
dist/artifact.html  Claude Artifact 用のフラグメント（生成物、doctype/head/body なし）
```

| コマンド | 内容 |
| --- | --- |
| `npm run build` | `src/` から `index.html` と `dist/artifact.html` を生成 |
| `npm test` | 全テスト（約13秒） |
| `npm run check` | ビルドしてからテスト |
| `npm run rank` | `src/rank-order.json` を再計算（約40秒） |

`src/evaluator.js` と `src/equity.js` はモジュール構文を持たないプレーンなスクリプトで、
ブラウザでは `<script>` に連結され、Node では `tools/load-engine.js` が同じ順序で同じスコープに読み込む。
テストが叩くバイト列と出荷されるバイト列が常に同一になる。
